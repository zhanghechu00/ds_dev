**`description` 字段就是控制工具调用条件的核心位置。**

---

## 一、核心原理

```json
{
    "type": "function",
    "function": {
        "name": "extract_heights_from_image",
        
        // 🎯 这里！这个description决定了Agent何时调用工具
        "description": "你的调用条件说明",
        
        "parameters": { ... }
    }
}
```

### 工作流程：

```
用户输入
    ↓
LLM读取所有工具的description
    ↓
匹配用户意图与工具描述
    ↓
决定是否调用（以及调用哪个工具）
    ↓
提取参数并执行
```

## 六、常见错误与解决

### ❌ **错误1：description太短**
```json
"description": "提取高程数据"
```
**后果：** LLM不知道何时调用

**解决：** 至少150-300字，包含条件、示例、排除

---

### ❌ **错误2：只有正面示例，没有反例**
```json
"description": "提取地形图高程。示例：'提取terrain.png'"
```
**后果：** LLM会过度调用（把不该调用的也调用）

**解决：** 必须包含"不应调用"的反例

---

### ❌ **错误3：描述模糊**
```json
"description": "处理图片数据"
```
**后果：** 所有涉及图片的请求都可能触发

**解决：** 明确说明"地形等高线图"、"包含标注"

---

### ❌ **错误4：没有关键词**
```json
"description": "分析用户提供的文件"
```
**后果：** LLM无法匹配语义

**解决：** 包含"地形图"、"等高线"、"高程"、"海拔"等关键词

## 七、description优化技巧

### 💡 **技巧1：使用结构化标记**

```
**调用条件：**（清晰分点）
**典型对话：**（真实示例）
✓/✗ 符号（视觉区分）
```

### 💡 **技巧2：包含用户的实际表达**

❌ 抽象："当需要处理地形时"  
✅ 具体："用户说'提取terrain.png的高程'"

### 💡 **技巧3：说明输出物**

```
**工具输出：**
生成extracted_heights.txt文件，包含grid_r × grid_c个高程值
```
帮助LLM判断是否符合用户需求

### 💡 **技巧4：添加反例（超级重要！）**

```
**不应调用：**
✗ 用户只询问不处理
✗ 图片不是等高线图
✗ 已经是数字数据
```
